# 이용자층, 지역, 하드웨어 보급 분포

전면 평가 Step 0-5(첫 실행 안내), Step 1-5(수집), Step 1-7(이용자층 적합 축)에서 읽는다.

## 1. 첫 실행 때 먼저 알릴 한계

대화 실행이고 market 리포트가 하나도 없으면(첫 실행), 수집을 시작하기 전에 아래 내용을 알린다. 무인 실행이면 같은 내용을 리포트의 "확인 못 한 것"에 적는다.

> 시작 전에 한계부터 말씀드려요. 장르 단위로 나눈 연령·성별 공개 자료는 거의 없어요. 그래서 이용자층은 두 가지로만 채워요. 하나는 자료가 원래 조사한 단위(국가 전체, 플랫폼 전체 등)를 밝힌 값이고, 다른 하나는 리뷰 언어 분포나 커뮤니티 규모 같은 간접 신호예요. 또 일부 통계 사이트는 자동 조회를 막아서, 그 값이 필요하면 화면 캡처나 CSV 로 넘겨 주셔야 해요.

## 2. 이용자층은 두 칸만 둔다

| 칸 | 들어가는 것 | 표기 |
|---|---|---|
| 확인된 단위의 값 | 공개 설문·공식 자료가 직접 조사한 값 | 값, **자료의 원래 단위**(국가 전체 게이머 / 플랫폼 이용자 / 장르 이용자 / 특정 게임 이용자), 표본, 연령 범위, 자료 기준 기간, 출처 번호 |
| 대신 쓸 수 있는 간접 신호 | 리뷰 언어 분포, 커뮤니티 규모(공식 커뮤니티 회원 수 등), 방송 시청 통계, 게임 동기 설문 공개 자료 | 앞에 [간접]. 무엇을 대신하는지, 한계(예: 동기 설문은 스스로 찾아와 답한 사람이 표본이라 열성 이용자 쪽으로 치우친다) |

## 3. 하지 않는 것

- 근거 없는 고정관념 문장을 쓰지 않는다. 예: "이 장르는 20~30대 남성 중심이다". 저장 전 점검에서 이런 문장을 찾아 지운다.
- 국가 전체 분포를 장르 이용자 분포처럼 옮기지 않는다. 플랫폼 이용자 분포도 마찬가지다.
- 장르 단위가 아닌 자료로 이용자층 적합 축에 '확인'을 주지 않는다.
- 한 지역의 자료로 다른 지역 칸을 채우지 않는다.
- 조사 방법(연령 범위, 표본, 연도)이 다른 지역 수치를 나란히 적기만 한다. "어디가 더 높다"는 비교 문장을 쓰지 않는다.
- 확인하지 못한 칸은 "확인 못 함"으로 둔다. 리포트 요약에 확인 못 한 칸 수를 적어 빈칸이 드러나게 한다.

## 4. 목표 이용자와 비교

- `market.target_player` 는 팀이 정한 결정이다. market 은 이 값을 바꾸지 않는다.
- 비교 결과는 "일치 / 어긋남 / 판단 보류" 중 하나다. `market.target_player` 가 비어 있으면 판단 보류다.
- 어긋나면 리포트의 "결정이 필요한 것"에 차이와 근거를 적고, 타깃을 정한 사람에게 확인할 질문으로 남긴다. design 고문은 프로필의 타깃만 쓰므로, 타깃을 바꿀지는 사람이 정한다.

## 5. 지역 표

- 프로필 `regions` 에 있는 지역만 다룬다. 지역마다 web-scout 를 하나씩, 한 메시지에서 병렬로 부른다.
- 지역마다 같은 여섯 칸을 채운다.

| 칸 | 내용 |
|---|---|
| 플랫폼 비중 | 그 지역의 플랫폼별 이용 또는 매출 비중. 자료 단위 표시 |
| 장르 신호 | 그 지역 공개 순위·설문에서 이 장르가 보이는 정도 |
| 가격·결제 관행 | 지역 가격 정책, 주로 쓰는 결제 수단, 부분 유료 관행 |
| 연령 등급·출시 허가 | 등급 기관과 기준, 정부 출시 허가 제도 |
| 언어·현지화 | 필요한 언어, 음성 현지화 관행 |
| 자료 공백 | 이 지역에서 찾지 못한 것. 반드시 채운다 |

지역별로 원문에서 확인할 것:

- 정부 출시 허가가 필요한 지역은 정식 출시와 글로벌 스토어를 거친 이용을 나눠 적는다.
- 판매 순위가 패키지만 세는지 디지털을 포함하는지, 금액 기준인지 수량 기준인지 원문에서 확인한다.
- PC방처럼 공용 시설 이용을 따로 집계하는 지역이면, PC 온라인 게임일 때 그 자료도 본다.
- 연령 등급 기준과 절차는 등급 기관 원문으로 확인한다.
- 금액은 그 지역 통화 그대로 적는다.

### 지역별로 먼저 볼 출처

지역마다 web-scout "양식 D" 지시문의 "먼저 볼 출처"에 아래 줄의 출처를 순서대로 이름과 주소로 적어 넣는다(web-scout 는 파일을 읽지 못한다). 주소와 작성 시 접근 확인 결과는 `metrics.md` §7 에 있다. 이 표도 정답 목록이 아니라 출발점이다. 프로필 `regions` 의 지역 이름에 맞는 줄을 고르고, 표에 없는 지역이면 web-scout 가 그 지역의 공공 기관·등급 기관·지역 매체를 찾게 한다.

| 지역 | 먼저 볼 출처 (순서대로) | 막혔거나 비어 있던 것 (작성 시) |
|---|---|---|
| 한국 | 한국콘텐츠진흥원 게임이용자 실태조사·게임백서 → 게임물관리위원회(등급) → 인벤(기사) | 진흥원 보고서 페이지 주소 확인 못 함. 디스이즈게임 403(접근 거부) |
| 일본 | 패미통 주간 판매 순위 → CERO(등급) | 일본 이용자 설문 출처는 작성 시 찾지 않음 |
| 북미 | ESA Essential Facts → Circana 보도자료 → PlayStation Blog 다운로드 순위 → ESRB(등급) → Game Developer(기사) | Circana 주소 확인 못 함(404). GamesIndustry.biz 도구가 막음 |
| 유럽 | PlayStation Blog 다운로드 순위 → PEGI(등급) | 유럽 이용자 설문 출처는 작성 시 찾지 않음. GamesIndustry.biz 도구가 막음 |
| 중국 | 국가신문출판서 출시 허가 공고 | 중국 시장·이용자 출처는 작성 시 찾지 않음. 첫 실행 때 양식 D 로 찾는다 |
| 지역 공통 | Steam 리뷰 공식 JSON 의 리뷰 언어 [간접] → Steam 하드웨어·소프트웨어 설문의 언어 비율 [간접] | SteamDB 403, Gamalytic 표 값 안 보임, Newzoo 도구가 막음, Quantic Foundry 403 |

막힌 출처는 "사람이 내보내 줘야 함"이다(`metrics.md` §6). 다른 주소로 돌아가 열지 않고, 필요하면 사용자에게 캡처나 CSV 를 받는다.

## 6. 하드웨어 보급 분포

- 이 조회는 market 만 한다. newtech 와 perf 는 프로필의 `target_spec` 만 읽는다.
- `platforms` 에 PC 가 있을 때만 조회한다. 플랫폼 공식 설문(예: Steam 하드웨어·소프트웨어 설문)의 최근 3개월 값을 모은다. 한 달 값으로 판단하지 않는다.
- 평균과 합계(예: 일정 메모리 이상 비율의 합)는 `market_calc.py stats` 로 계산한다.
- 이 설문으로 장르별 사양이나 국가별 판매 비중은 말할 수 없다. 설문의 언어 분포는 [간접] 신호다.
- 결과는 `target_spec` 을 바꾸자는 **제안**까지만 한다. 리포트의 "결정이 필요한 것"에 바꿀 값, 근거(출처 번호, 몇 개월 평균), 지금 값을 적는다. 대화 실행에서 사용자가 확정하면 그때 프로필에 쓰고 `updated` 를 오늘 날짜로 바꾼다. 무인 실행에서는 프로필을 쓰지 않는다.
