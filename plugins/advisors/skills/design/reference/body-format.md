# 기획 고문 리포트 본문 양식

공통 머리와 항목 순서는 `shared/report-base.md` 를 따른다. 이 파일은 그 양식의 "## 본문" 자리에 넣을 내용과, 머리의 '범위' 칸에 적을 것을 정한다.
영역 진단 Step A4, 단건 심사 Step B4 에서 읽는다.

## 머리의 '범위' 칸

다음을 해당될 때만 한 줄씩 적는다.

- 모드와 대상: `영역 진단 — <영역 이름> (<영역 폴더 또는 영역 파일 패턴>)` 또는 `단건 심사 — <대상 한 줄>`
- 읽은 기획서 수 / 상한: `읽은 기획서 32 / 상한 40, 상한 초과 12`
- `가안 기준` — 원칙이 가안일 때
- `원칙 미확정 — 판정 없음` — 원칙이 없거나 확인받지 못했을 때
- `수치 근거 없음 단계` — 데이터가 임시값일 때
- `참고 선택지` — 사용자가 기획 결정권자가 아닐 때
- `에이전트 없이 메인에서 수집함` — 서브에이전트를 부르지 못했을 때

리포트 제목은 `# 기획 고문 영역 진단 — YYYY-MM-DD` 또는 `# 기획 고문 단건 심사 — YYYY-MM-DD`.

## 영역 진단 본문

```markdown

### 0. 기준
- 원칙: <문서:단락> / 상태 확정·가안 / 확인 기록 <프로필 design.principles_confirmed 의 날짜, 리비전. 비었으면 '없음'> / 그 뒤 원칙 문서 변경 <있음·없음·확인 못 함>
- 데이터 상태: 확정 / 임시값
- 근거 등급 표시: [관찰-행동] [관찰-의견] [계산] [문서] [문서-의도] [추정]

|---|---|---|---|---|

| 시스템 | 연결 원칙 | 붙은 고리 | 체크리스트 | 선택 | 위험-보상 | 역할 중복 | 구현 단계 | 근거 등급 | 판정 |

### 9. 지난 제안 확인 (제안 기록에 '채택'·'검증 중' 항목이 있을 때)

### 부록
#### 계산 — 실행한 명령, 입력 위치, 출력 전문
#### 인용 목록 — 위치와 날짜
```

## 제안 카드

두 모드에서 같은 양식을 쓴다. 칸을 비우지 않는다. 해당하지 않으면 '해당 없음'과 이유를 쓴다.

```markdown
#### <제안 ID> <제목>
- 종류: 추가 / 수정(수치) / 수정(구조) / 보류 / 제거 권고 / 통합
- 원칙: 기여하는 것 <층·이름·인용 위치> / 해치는 것 <…> / 금지 원칙 점검 결과
- 플레이어가 겪는 장면: <한 줄. 누가, 언제, 무엇을 하다가 무엇을 겪는가>
- 입력 → 규칙 → 결과: <추가·수정(구조)일 때>
- 근거: <내용> [등급] <위치> (여러 줄)
- 반대 근거: <내용> [등급] <위치>
- 남겨야 하는 이유 (보류·제거·통합일 때 먼저 쓴 것):
- 되살릴 조건 (보류일 때):
- 의존 범위 (제거·통합일 때): <참조하는 코드·데이터·콘텐츠 목록, 검색 범위와 패턴>
- 수치 (수정(수치)일 때): <값의 실제 의미> = [PLACEHOLDER] <시작값>, 이유:
- 기회비용 (추가일 때): <이것을 하면 미루는 것>
- 재미 기여도: 상·중·하 — 이유
- 비용: S·M·L·L+ — 바뀌는 시스템과 위치 / 새 에셋 / 네트워크 동기화 / 기존 콘텐츠 재작업. 담당 프로그래머 확인 필요
- 성능 부담: 없음 / 있음 — 성능 미확인, 질문 <Q-ID>
- 우선순위: 1·2·3·보관 — 이유
- 틀렸다면 그 이유 (우선순위 1·2): 1) … 2) … — 반박 결과
- 검증 방법: (아래 양식, 또는 기존 도구 형식의 후보)
- 넘긴 질문: <Q-ID 목록>
- 최소 조건 점검: | 조건 | 충족 | 근거 위치 |
```

## 검증 방법

```markdown
- 관찰 장면: <그 메커닉이 실제로 쓰이는 순간. 세션 평균이나 연습장이 아님>
- 관찰 신호: <행동 위주. 시도 횟수, 선택 비율, 다시 도전하는지 등>
- 성공 / 실패: <방향은 확정, 기준 수치는 [PLACEHOLDER]>. 테스트 전에 적는다
- 조건: <인원, 숙련도 구성, 판 수>
- 측정 수단: 관찰 메모 / 플레이 로그(그 로그가 코드에 있는지 확인한 결과, 없으면 '로그 추가 필요') / 설문(질문 원문까지)
```

무엇을 관찰해도 맞았다고 할 수 있는 계획은 검증이 아니다. 다시 쓴다.

## 게임 전체 목차

대상이 '게임 전체'일 때만 만든다. 새 판정은 하지 않고, 영역별 최근 영역 진단 리포트를 모아 보여 준다. 무인 실행에서는 영역 진단을 새로 돌리지 않으므로 이미 있는 리포트로만 만든다.
파일: `<report_dir>/design/<YYYY-MM-DD>-area-index.md`. 공통 머리는 쓰되 본문은 아래만.

```markdown
## 본문

| 영역 | 최근 리포트 | 작성일 | 기준 리비전 | 원칙 상태 | 상위 제안(최대 3) | 오래됨 |
|---|---|---|---|---|---|---|
| <영역> | <경로> | YYYY-MM-DD | <값> | 확정·가안 | DP-…, DP-… | 예/아니오 |
| <영역> | 진단 안 함 | - | - | - | - | - |

- 영역 사이에 걸친 제안(두 영역 리포트에 같은 시스템이 나온 경우): <제안 ID, 영역들>
- 오래됨: 프로필 stale_after_days 보다 오래된 리포트
```
