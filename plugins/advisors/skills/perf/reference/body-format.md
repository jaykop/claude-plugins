# 최적화 리포트 본문 양식

리포트 전체는 `<플러그인 폴더>/shared/report-base.md` 의 머리와 항목 순서를 따른다. 아래는 그 양식의 "본문" 자리에 넣는 내용이다. 내용이 없는 항목은 제목만 두지 말고 "해당 없음"이라고 한 줄 적는다.

- 파일 이름: `<report_dir>/perf/<YYYY-MM-DD>-diagnosis.md`(진단) 또는 `<report_dir>/perf/<YYYY-MM-DD>-periodic.md`(주기 점검). 날짜는 작성일이고, 모드 부분은 영어 소문자로만 쓴다(공통 규칙 §12).
- 머리의 "범위"에는 대상(증상·시스템·파일·질문 ID), 시나리오 ID, 쓴 측정 파일 수를 적는다. 서브에이전트 없이 메인에서 읽었으면 "에이전트 없이 메인에서 수집함"을 덧붙인다.
- 영어 용어는 처음 나올 때 뜻을 풀어 쓴다(공통 규칙 §11). 예: p95(느린 쪽 5% 를 뺀 경계값), 포함 시간(하위 호출까지 합친 시간).

## 진단

```markdown
### 1. 범위와 기준
| 항목 | 값 |
|---|---|
| 대상 | <증상 / 시스템 경로 / 파일 / 질문함 ID> |
| 시나리오 | <ID와 한 줄 설명> |
| 예산 기준 | <perf.budgets 의 값 / "예산 없음 — 대체 순위 규칙"> |
| 측정 주체 | <perf.measured_by> |
| 측정 자료 | <쓴 파일 목록 / "측정 없음 — 이번 결과물은 측정 계획"> |

### 2. 측정 조건
<회차마다 measure.md 2번 항목의 표. 측정이 없으면 "해당 없음">

### 3. 프레임 개요 (병목 판정)
| 시나리오 | 지표 | 프레임 | 게임 스레드 | 렌더 스레드 | RHI 스레드 | GPU | 병목 | 예산 | 히치 프레임 | 출처 |
|---|---|---|---|---|---|---|---|---|---|---|
| S01 | p50 / p95 / 최대 (ms) | | | | | | | | | <파일, 명령> |

### 4. 확인된 문제 [확인]
#### 4.1 <항목 ID> <제목> — <1순위 / 2순위 / 3순위>
- 측정값: <값> (파일: <경로>, 명령·채널: <...>, 구간: <...>, 반복: <N회, 흩어짐>)
- 원인 코드: <파일:줄> (호출 경로: <파일:함수 → 파일:함수>)
- 개선안: <무엇을 어떻게. 게임 코드·설정 쪽을 먼저 본다>
- 효과 상한: <이 구간의 포함 시간>. <병목이면 "프레임 시간이 최대 ... 줄 수 있다" / 아니면 "<스레드> 여유가 최대 ... 생긴다">
- 재측정 방법: <같은 조건, 같은 구간>
- 승인 등급: <내 작업 범위 / 팀 공유 필요>

### 5. 의심 목록 [의심] (측정 전, 10건까지)
| 측정 순서 | 항목 ID | 위치 (파일:줄) | 패턴 | 호출 빈도와 근거 (파일:함수 경로) | 그 코드를 가진 객체 수 근거 | 확인할 측정 |
|---|---|---|---|---|---|---|

- 잘린 의심: <N건 — 호출 빈도와 객체 수 기준으로 잘림>
- 제외한 검색 결과: <한 번만 불리는 것 등, 파일:줄과 사유>
- 검색 기록: <범위, 패턴, 결과 개수, 실패 여부>

### 6. 측정 계획
<measure.md 4번 항목의 양식. 3개 이내. 측정이 충분하면 "해당 없음">

### 7. 리팩터링 판단
<refactor.md 4번 항목의 표. 판단하지 않았으면 "해당 없음">

### 8. 테스트 제안
<tests.md 3번 항목의 명세. 없으면 "해당 없음">

### 9. 근거 확인 기록
- 쓴 콘솔 명령·콘솔 변수·명령줄 인자와 실재 확인 위치(파일:줄) 또는 "확인 필요"
- 실행한 스크립트 명령과 그 출력 중 판단에 쓴 표
```

## 주기 점검

```markdown
### 1. 회차 정보
| 항목 | 값 |
|---|---|
| 이번 회차 | R-<번호> (<날짜>) |
| 새 측정 파일 | <profiling_dir 기준 상대 경로 목록과 시나리오 ID. "시나리오 미상"으로 뺀 파일은 따로 적는다> |
| 측정 조건 | C-<번호> — <measure.md 2번 항목의 칸 요약>, 사용자 확인 <예 / 아니오(무인)> |
| 비교한 회차 | 직전 R-<번호> (조건 일치 / 다른 칸: ...), 기준선 R-<번호> (조건 일치 / 다른 칸: ...). 첫 회차면 "없음(첫 회차)", 기준선이 없으면 "기준선 없음" |

### 2. 이번에 본 범위와 고른 이유
| 부문 또는 항목 | 고른 이유 |
|---|---|
| | ① 지난 회차에서 나빠짐 / ② 이 기간 변경이 건드림(변경 N개. 읽기 명령이 허용되지 않았거나 조회에 실패했으면 "조회 안 함") / ③ 가장 오래 안 본 부문(마지막 점검일) / 질문함 요청(Q-번호) |

### 3. 변화
| 항목 ID | 시나리오 | 지표 | 기준선 | 직전 | 이번 (중앙값) | 흩어짐 | 직전 대비 | 기준선 대비 | 판정 | 원인 후보 변경 |
|---|---|---|---|---|---|---|---|---|---|---|

- 판정: 통과 / 주의 / 초과 / 측정 못 함 / 비교 불가. "누적 악화"는 판정 칸에 덧붙인다.
- 원인 후보는 후보일 뿐이다. 확정은 두 리비전 사이를 나눠 재는 측정으로 제안한다.

### 4. 나빠진 항목 상세
#### 4.1 <항목 ID> <제목>
- 변화: <식과 값, 비교 명령>
- 원인 후보: <변경 번호와 건드린 경로>
- 의심 코드: <그 부문 패턴을 변경된 경로에만 돌린 결과, 10건까지>
- 다음 측정: <측정 계획 번호>

### 5. 기준선
<"기준선 후보: R-<번호> — 사용자 확인 필요" / "기준선 변경 없음">

### 6. 근거 확인 기록
<진단 양식의 9번과 같다>
```

## 대화에 내는 것

리포트 전문은 파일로만 둔다. 대화에는 공통 규칙 §9 대로 요약 세 줄, 결정이 필요한 것, 리포트 경로, 후속 제안 1~3개만 낸다.
