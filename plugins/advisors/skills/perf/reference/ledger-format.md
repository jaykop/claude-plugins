# 점검 기록 형식 (`_state/perf-ledger.md`)

최적화 고문만 쓰고 읽는 기록이다. 위치는 `<report_dir>/_state/perf-ledger.md`. 회차마다 덧붙이고, 지난 행을 지우지 않는다. 다른 고문이 측정값을 원하면 이 파일이 아니라 리포트를 인용한다.

## 머리

모든 `_state` 파일과 같은 머리를 쓴다(`${CLAUDE_PLUGIN_ROOT}/shared/state-formats.md`).

```markdown
# 최적화 점검 기록

다음 점검: YYYY-MM-DD
작성: perf / 마지막 갱신: YYYY-MM-DD / 기준 리비전: <변경 번호 또는 커밋>
```

- `다음 점검:` 은 마지막 실행일에 기본 주기(7일)를 더한 날짜다. 날짜 계산은 `date -d "+7 days" +%F`(GNU) 또는 `date -v+7d +%F`(macOS)로 한다. 사용자가 다른 주기를 정했으면 그 값을 쓴다.
- 새 측정 파일이 없어 리포트를 만들지 않은 실행도 이 줄을 갱신한다.

## 1. 판정 기준

프로필에 칸이 없는 최적화 전용 값이다. 사용자가 정한 값만 `[사용자]` 출처로 적는다. 비어 있는 값을 고문이 지어 채우지 않는다. `refactor.md` 3번 항목의 임시 기준처럼 이번 실행에만 쓴 값은 리포트에만 적고 여기에는 적지 않는다.

```markdown
## 판정 기준
| 값 | 설정 | 출처 |
|---|---|---|
| 측정 파일 이름 규칙 | <파일 이름이나 하위 폴더에서 시나리오 ID 를 읽는 규칙. 예: `<시나리오 ID>_` 로 시작 / 시나리오 ID 이름의 하위 폴더> | |
| 히치 기준(ms) | | |
| 최소 변화폭 | <값과 단위(ms 또는 %). 지표별로 다르면 행을 나눈다> | |
| 리팩터링 이력 기간(일) | | |
| 티켓 키 접두사 | | |
| 버그로 셀 이슈 종류·라벨 | | |
| 변경 비용 기준 | | |
| 버그 빈도 기준 | | |
| 점검 제외 경로(폐기 예정 코드) | | |
| 기준선 회차 | R-<번호> | |
```

## 2. 부문별 경로

주기 점검에서 "그 기간 변경이 건드린 부문"을 고르고, 그 부문의 코드 의심 패턴을 돌릴 범위로 쓴다. 사용자가 확인한 값만 넣는다.

- 코드·설정 경로는 analyst 의 코드 검색 범위다. 프로젝트 루트 기준 glob 으로 적는다.
- 버전 관리 경로는 `vcs_churn.py --path` 로 그대로 넘긴다. git 이면 프로젝트 루트 기준 폴더 경로, p4 면 depot 경로(`//` 로 시작하고 `/...` 로 끝나는 꼴)로 적는다. p4 에 다른 꼴을 주면 스크립트가 파일을 경로로 거르지 못한다.

```markdown
## 부문별 경로
| 부문 | 코드·설정 경로 (glob) | 버전 관리 경로 | 확인일 |
|---|---|---|---|
| 게임 스레드 CPU — AI | Source/<모듈>/AI/** | git: Source/<모듈>/AI/ 또는 p4: //<depot>/<경로>/Source/<모듈>/AI/... | YYYY-MM-DD |
```

## 3. 측정 조건

측정 조건 점검표(`measure.md` 2번 항목)의 칸을 그대로 쓴다. 조건 ID 는 `C-` 뒤에 세 자리 번호다. 조건이 같은 회차는 같은 조건 ID 를 쓴다.

```markdown
## 측정 조건
| 조건 ID | 빌드 구성 | 프레임 상한·수직 동기화 | 창 비활성 제한 | 워밍업 | 반복 | 해상도·화질 | 플랫폼·하드웨어 | 엔진·빌드 리비전 | 임시로 바꾼 설정 | 사용자 확인 |
|---|---|---|---|---|---|---|---|---|---|---|
| C-001 | | | | | | | | | | 예 / 아니오 |
```

## 4. 회차

회차 ID 는 `R-` 뒤에 세 자리 번호다.

```markdown
## 회차
| 회차 | 날짜 | 실행 방식 | 조건 ID | 시나리오 | 측정 파일 | 비교한 회차 | 기준선 여부 | 리포트 |
|---|---|---|---|---|---|---|---|---|
| R-001 | YYYY-MM-DD | 대화 | C-001 | S01 | <profiling_dir 기준 상대 경로 목록> | 없음(첫 회차) | 기준선 | perf/YYYY-MM-DD-periodic.md |
```

- "측정 파일" 칸은 새 측정 파일을 가려내는 기준이다. 여기에 적힌 적 없는 파일이 `perf.profiling_dir` 에 있으면 새 파일이다. 파일 시스템 수정 시각은 쓰지 않는다.
- "기준선 여부"는 측정 조건 표의 칸이 모두 채워지고 사용자가 확인한 회차만 "기준선"이 될 수 있다. 무인 실행에서 나온 회차는 "기준선 후보"까지만 쓴다.
- 기준선을 바꾸면 판정 기준 표의 "기준선 회차"를 바꾸고, 바꾼 날과 이유를 회차 표 아래에 한 줄로 남긴다.

## 5. 항목

부문·항목 분류표(`categories.md`)의 ID 를 쓴다. 한 항목을 여러 시나리오·지표로 재면 행을 나눈다.

```markdown
## 항목
| 항목 ID | 시나리오 | 지표 | 마지막 점검일 | 점검 방법 | 기준선 값 (회차) | 직전 값 (회차) | 판정 | 근거 표시 | 측정 파일 |
|---|---|---|---|---|---|---|---|---|---|
| 게임스레드-01 | S01 | 게임 스레드 시간 p95 (ms) | YYYY-MM-DD | CSV 프로파일러, csv_profile_stat.py compare | 12.4 (R-001) | 12.9 (R-003) | 주의 | [확인] | <경로> |
```

- "마지막 점검일"은 주기 점검의 ③(가장 오래 안 본 부문 하나)을 고를 때 쓴다. 한 번도 안 본 부문은 "없음"으로 두고 가장 먼저 고른다. 후보가 여럿이면 `categories.md` 3번 항목의 표 순서로 앞의 것을 고른다.
- "판정"은 통과 / 주의 / 초과 / 측정 못 함 / 비교 불가 중 하나다. 첫 회차이고 예산도 없을 때만 "-" 로 둔다(`grades.md` 6번 항목).
- 이번에 재지 않은 항목은 값을 바꾸지 않는다. 직전 값을 이번 값처럼 옮기지 않는다.

## 7. 측정 없음 기록

새 측정 파일이 없어 리포트를 만들지 않은 실행을 한 줄씩 남긴다.

```markdown
## 측정 없음 기록
| 날짜 | 실행 방식 | 요청한 측정 |
|---|---|---|
| YYYY-MM-DD | 무인 | 없음 (무인 실행이라 요청하지 않음) |
| YYYY-MM-DD | 대화 | S01 을 측정 계획 MP-002 대로 재 달라고 요청 |
```
