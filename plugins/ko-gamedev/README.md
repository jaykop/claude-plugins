# ko-gamedev — 게임 프로젝트 한국어 교정

게임 프로젝트의 한국어를 쓰고 교정하는 플러그인이다. 코드 주석과 기술 문서는 한국 게임 개발자가 실제로 쓰는 용어와 문체로(style), 시놉시스와 소개문 같은 이야기 문서는 한국어 책의 문장으로(prose) 맞춘다.

```
/plugin install ko-gamedev --marketplace jaykop/claude-plugins
```

마켓플레이스를 이미 추가했으면 `/plugin install ko-gamedev@jaykop` 로도 설치된다.

| 스킬 | 명령 | 하는 일 |
|---|---|---|
| style | `/ko-gamedev:style` | 한국어 주석·문서를 새로 쓸 때 용어와 문체를 맞추고, 기존 주석·문서를 검토하거나 고친다 |
| prose | `/ko-gamedev:prose` | 시놉시스, 소개문, 기획의도, 인물 소개, 기획 문서의 이야기 부분, 내레이션을 쓰거나 검토하고 고친다 |

명령 이름을 외우지 않아도 된다. "주석 한국어 다듬어 줘", "업계 용어로 고쳐 줘", "AI 말투 같은 주석 정리해 줘", "이 설계 문서 문체 교정해 줘" 같은 말로 style이, "시놉시스 문장 다듬어 줘", "소개문이 AI가 쓴 것 같아", "무슨 말인지 모르겠어" 같은 말로 prose가 불린다. 게임 프로젝트에서 한국어 주석, 문서, 이야기 문서를 쓰는 작업이면 스스로 불러 쓴다.

```
/ko-gamedev:style Source/ 검토만
/ko-gamedev:style Plugins/MyPlugin 수정
```

`검토만`은 파일을 고치지 않고 위치, 원문, 교정안, 이유를 표로 보고한다. `수정`은 주석과 문서의 한국어만 고치고 식별자, 문자열, 메타데이터, 코드, 인코딩, 줄바꿈은 그대로 둔다.

## 무엇을 바꾸나

AI가 쓴 한국어는 업계 주석과 반대 방향으로 기운다. 이 플러그인은 그 차이를 업계 쪽으로 되돌린다.

| AI가 쓴 한국어 | 업계 주석 |
|---|---|
| 순화한 고유어 동사: 쓴다, 돌려준다, 고른다, 바꾼다, 남긴다 | 한자어·외래어 동사: 사용한다, 반환한다, 선택한다, 변경한다, 출력한다 |
| 번역한 엔진 용어: 편집기, 저작, 사본, 구독, 시각 | 에디터, 에디터용, 복사본, 바인딩, 시점 |
| 모든 주석을 `~다` 문장으로 | 필드·인라인 주석은 개조식 명사 종결, 설명만 `~한다` |
| 가운뎃점(·) 나열, `~므로` 연쇄, `~한 뒤` | 쉼표나 `/`, `때문에`, `~ 후` |

사람이 쓴 주석의 오타(애니매이션, 악세서리)와 구어(일단, 그냥, ...)도 함께 잡는다.

주석은 코드만 보고 이해할 수 있어야 한다. 기획서, 문서, 이슈를 참조하거나 변경 이력을 적지 않는다. 변수와 에디터 툴팁으로 보이는 주석은 값의 역할과 용도, 단위, 특수 값만 쓰고, 그 값을 사용하는 로직은 함수 주석에 둔다. 이 규칙은 말뭉치 측정 결과가 아니라 사용자의 선택이다.

엔진 타입 이름(Actor, Component, Mesh, Tick, Montage, Widget 등)은 본문에서도 영어로 쓴다. 사람이 쓴 주석은 액터, 컴포넌트처럼 음차하지만, 이 플러그인은 영어 이름을 쓴다. 콜리전, 트레이스, 스폰처럼 개념이나 동작을 뜻하는 말은 한국어 외래어로 둔다.

## 구성

```
skills/style/
  SKILL.md            절차: 읽을 파일, 작성·검토·수정 순서, 보고 형식
  glossary/           분야별 용어집. 표가 곧 검사 규칙이다
    README.md         표 형식, 근거 표기, 표기 원칙, 프로젝트 용어 파일
    core.md           모든 분야의 동사, 조건, 명사, 프로그래밍 용어, 직역투, 번역체, 구어
    spelling.md       외래어 표기 통일
    unreal.md         엔진, 에디터, 네트워크, 콜리전, 입력, GAS, 렌더링과 성능
    combat.md         타겟, 락온, 대미지, 피격, 빈사와 사망, 방어, 스킬
    animation.md      애님 에셋, 블렌드, 스테이트, 로코모션
    systems.md        AI와 Perception, 스폰, 탈것, 아이템, 카메라, UI, 제작 용어
  style/
    comments.md       코드 주석 문체
    documents.md      설계·기술 문서 문체
    ai-tells.md       AI가 쓴 한국어의 특징과 근거 수치
  scripts/ko_lint.py  용어집 표를 읽어 주석과 문서에서만 후보를 찾는다
```

용어집의 각 행에는 근거 수치가 붙어 있다. 사람이 쓴 상용 UE5 게임의 주석(A, 비공개), 2022년 이전에 공개된 한국 개발자의 게임 프로젝트 주석(O), AI가 주로 쓴 UE5 프로젝트의 주석(K), 애니메이션 설계 문서(D)에서 1,000건당 등장 수를 쟀다. 번역체 행은 한국어 기술 글쓰기 가이드(W)를 근거로 한다. 사람이 쓴 블로그(B)에서 AI 문서보다 더 자주 나오기 때문에 AI 말투의 표시가 아니라 문체 조언이고, `review`와 `density`로만 둔다.

게임 개발자 한 명이 쓴 공개 기술 블로그(B)는 문서 1,000줄당 수로 따로 쟀다. 철자 오타, 검사 오탐, 카메라와 입력처럼 빠졌던 분야의 용어를 찾는 데 썼다. 글쓴이가 이 플러그인의 관리자 본인이라서 업계 빈도의 근거로는 쓰지 않는다. 자세한 내용은 [glossary/README.md](skills/style/glossary/README.md#evidence)에 있다.

## 검사 스크립트

스킬이 교정할 때 직접 실행한다. 사람이 따로 돌려도 된다.

```
python skills/style/scripts/ko_lint.py --summary <폴더>
python skills/style/scripts/ko_lint.py --kind replace,review,density <파일>
```

C++, C#, Python, GDScript 의 주석, ini 의 `DevComment`, Markdown 의 코드 밖 본문만 읽는다. 결과는 후보일 뿐이다. `replace`는 거의 항상 고칠 것, `review`는 문맥을 보고 정할 것, `density`는 한 파일에 몰리면 문제인 표현이다. 검사 결과 예시(한국어 주석 1,000줄당 후보): 사람이 쓴 코드 64~91건, AI가 쓴 코드 1,091건. 문서는 1,000줄당 사람이 쓴 블로그(B) 150~234건, AI가 쓴 문서 842건이다. 블로그 수치에는 엔진 타입 이름을 영어로 쓰는 규칙에 걸린 후보도 들어 있다.

## 프로젝트 용어

프로젝트가 따로 정한 말은 프로젝트 루트의 `.claude/ko-gamedev/terms.md`에 둔다. 용어집과 같은 표 형식으로 행을 더하고, `Allow` 표로 기본 규칙을 끈다. 예를 들어 락온을 하드락 대신 쓰는 프로젝트, 자체 그래프에서 `전이`를 용어로 정한 프로젝트가 여기에 적는다. 형식은 [glossary/README.md](skills/style/glossary/README.md#project-terms-file)를 따른다.

## 범위 밖 (style)

영어 문서, 플레이어에게 보이는 UI·현지화 문자열, 게임 개발과 무관한 일반 글, 코드 로직 변경은 다루지 않는다. 프로젝트 지침이 주석을 영어로 쓰라고 정했으면 새 주석은 영어로 쓰고, 기존 한국어 주석은 다듬을지 영어로 옮길지 먼저 묻는다.

## prose — 이야기 문서

AI가 쓴 한국어 기획 문서는 사실을 같은 꼴의 평서문으로 줄줄이 쌓는다. 인물의 계산을 주인 없이 세상의 법칙처럼 적고, 고유어 동사 하나(넘기다, 알다, 보다)에 뜻 대여섯 가지를 싣는다. 읽는 사람은 쓴 사람의 머릿속을 다시 짜 맞춰야 줄거리를 따라간다. prose는 이것을 한국어 책에서 잰 문장 규칙으로 고친다.

| AI가 쓴 이야기 문서 | 한국어 책과 전문가 소개문 |
|---|---|
| 인물의 계산을 일반 현재형 조건문으로 끼운다(조건문 `-면` 100문장당 16~18개, "~라야 ~한다") | 이유를 그 인물의 행동 문장 안에 붙인다(`-려고`, `-니까`, `~할까 봐`. 조건문 3.5~6.2개) |
| 접속어로 여는 문장 1,000문장당 16~17개, 전환 접속어 0% | 51~85개. 전환점은 그런데, 하지만, 그러던 어느 날로 표시 |
| 날짜와 요일로 여는 문장 21% | 약 1%. 시간은 전환점에만 |
| 넘기다, 안다, 본다, 둔다를 책보다 6~30배 | 뜻마다 제 동사: 맡기다, 건네다, 내주다, 고발하다, 전해 듣다, 목격하다 |
| 무너지다, 남다, 드러나다, 이어지다로 줄거리 논리를 설명 | 기소가 어렵다, 기록된다, 들통난다, 수사가 미친다 |
| 자리, 일, 몫, 줄, 손, 셈 같은 뜻이 갈리는 짧은 명사 | 위치, 의뢰, 상납금, 연줄, 부릴 사람, 저울질 |
| 인물 한 줄이 직업과 "-려 한다" 목표뿐, 형용사 0 | 지금 처지, 묶인 것, 하는 일, 주인공과의 관계 |
| (교정하다 생기는 틀) "~라는 것이 X의 계산이다", "이렇게 따진다", "남은 문제는" | 책 790만 자에 거의 없음. 이유를 행동 문장 안에 접는다 |

근거는 한국어로 쓴 소설 31권, 한국인이 쓴 작법서와 영화 책 37권, 드라마·영화 대본집의 인물 소개와 작가의 말, 그리고 독자가 읽어 내지 못한 AI 기획 문서다. 책 문장은 옮기지 않았고 예문은 새로 지었다. 자세한 수치와 출처는 [skills/prose/glossary/README.md](skills/prose/glossary/README.md#evidence)에 있다.

```
skills/prose/
  SKILL.md              절차: 읽을 파일, 작성·교정·검토 순서, 새 독자 확인, 보고 형식
  glossary/README.md    표 형식, Base 열, 코퍼스와 근거
  glossary/words.md     만능 동사, 줄거리 논리 비유 동사, 막연한 명사, 어린이 말투와 틀린 짝
  style/ai-tells.md     AI가 쓴 이야기 문서의 특징과 근거 수치
  style/sentences.md    문단과 문장 잇기 규칙 S1~S12, 고쳐쓰기 순서, 점검법
  style/words.md        어휘 선택 규칙 W1~W9
  style/introductions.md 로그라인, 기획의도, 시놉시스, 인물 소개 규칙 I1~I9
  style/examples.md     지어낸 이야기로 보인 고치기 전후
  scripts/prose_lint.py 용어집 후보, 주인 없는 조건문, 긴 문장, 괄호 연쇄, 책과 비교한 문장 지표
```

```
python skills/prose/scripts/prose_lint.py --summary <파일이나 폴더>
python skills/prose/scripts/prose_lint.py --kind density <파일>
```

Markdown과 텍스트의 코드 밖, 따옴표 밖 본문만 읽는다. 따옴표 안은 대개 인물 대사나 지어낸 용어라서 건너뛴다(`--include-quotes`로 포함). `density` 행은 파일의 빈도가 책 기준값(`Base`)의 3배 이상일 때만 줄을 보여 준다. 검사 예시: AI가 쓴 기획 문서 한 편(한글 1만 자)에서 review 19건과 밀도 경고 12종 103건, 소설과 작법서 한 권(한글 8만~23만 자)에서 review 0~16건과 밀도 경고 0~1종. `owner`(주인 없는 조건문)는 1,000문장당 소설 1.1건, AI 소개문 25건이다. 사람이 쓴 작법서는 7.6건인데, 작법서는 글쓴이가 규칙을 직접 말하는 글이라서다.

이야기 구조, 사건 사슬, 대사의 말투, 대본 형식은 story 플러그인의 `story:write`가 맡는다. prose는 문장만 고치고, 고치다가 찾은 줄거리 문제(원인 없는 사건, 빠진 동기)는 보고만 한다. 프로젝트가 따로 정한 말은 `.claude/ko-gamedev/prose-terms.md`에 둔다. style의 `terms.md`와 따로 두는 이유는 두 스킬이 같은 동사를 반대로 다루기 때문이다.
