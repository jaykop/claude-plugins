# ko-gamedev — 한국 게임 업계 용어·문체 교정

게임 프로젝트의 한국어 코드 주석과 기술 문서를 한국 게임 개발자가 실제로 쓰는 용어와 문체로 쓰고 교정하는 플러그인이다.

```
/plugin install ko-gamedev --marketplace jaykop/claude-plugins
```

마켓플레이스를 이미 추가했으면 `/plugin install ko-gamedev@jaykop` 로도 설치된다.

| 스킬 | 명령 | 하는 일 |
|---|---|---|
| style | `/ko-gamedev:style` | 한국어 주석·문서를 새로 쓸 때 용어와 문체를 맞추고, 기존 주석·문서를 검토하거나 고친다 |

명령 이름을 외우지 않아도 된다. "주석 한국어 다듬어 줘", "업계 용어로 고쳐 줘", "AI 말투 같은 주석 정리해 줘", "이 설계 문서 문체 교정해 줘" 같은 말로도 불린다. 게임 프로젝트에서 한국어 주석이나 문서를 쓰는 작업이면 스스로 불러 쓴다.

```
/ko-gamedev:style Source/ 검토만
/ko-gamedev:style Plugins/MyPlugin 수정
```

`검토만`은 파일을 고치지 않고 위치, 원문, 교정안, 이유를 표로 보고한다. `수정`은 주석과 문서의 한국어만 고치고 식별자, 문자열, 메타데이터, 코드, 인코딩, 줄바꿈은 그대로 둔다.

## 무엇을 바꾸나

AI가 쓴 한국어는 업계 주석과 반대 방향으로 기운다. 이 플러그인은 그 차이를 업계 쪽으로 되돌린다.

| AI가 쓴 한국어 | 업계 주석 |
|---|---|
| 순화한 고유어 동사: 쓴다, 돌려준다, 고른다, 바꾼다, 남긴다 | 한자어·외래어 동사: 사용한다, 반환한다, 선택한다, 변경한다, 출력한다 |
| 번역한 엔진 용어: 편집기, 저작, 사본, 구독, 시각 | 에디터, 에디터용, 복사본, 바인딩, 시점 |
| 모든 주석을 `~다` 문장으로 | 필드·인라인 주석은 개조식 명사 종결, 설명만 `~한다` |
| 가운뎃점(·) 나열, `~므로` 연쇄, `~한 뒤` | 쉼표나 `/`, `때문에`, `~ 후` |

사람이 쓴 주석의 오타(애니매이션, 악세서리)와 구어(일단, 그냥, ...)도 함께 잡는다.

엔진 타입 이름(Actor, Component, Mesh, Tick, Montage, Widget 등)은 본문에서도 영어로 쓴다. 사람이 쓴 주석은 액터, 컴포넌트처럼 음차하지만, 이 플러그인은 영어 이름을 쓴다. 콜리전, 트레이스, 스폰처럼 개념이나 동작을 뜻하는 말은 한국어 외래어로 둔다.

## 구성

```
skills/style/
  SKILL.md            절차: 읽을 파일, 작성·검토·수정 순서, 보고 형식
  glossary/           분야별 용어집. 표가 곧 검사 규칙이다
    README.md         표 형식, 근거 표기, 표기 원칙, 프로젝트 용어 파일
    core.md           모든 분야의 동사, 조건, 명사, 직역투, 번역체, 구어
    spelling.md       외래어 표기 통일
    unreal.md         엔진, 에디터, 네트워크, 콜리전, GAS
    combat.md         타겟, 락온, 대미지, 피격, 방어, 스킬
    animation.md      애님 에셋, 블렌드, 스테이트, 로코모션
    systems.md        AI, 스폰, 아이템, UI, 제작 용어
  style/
    comments.md       코드 주석 문체
    documents.md      설계·기술 문서 문체
    ai-tells.md       AI가 쓴 한국어의 특징과 근거 수치
  scripts/ko_lint.py  용어집 표를 읽어 주석과 문서에서만 후보를 찾는다
```

용어집의 각 행에는 근거 수치가 붙어 있다. 사람이 쓴 상용 UE5 게임의 주석(A, 비공개), 2022년 이전에 공개된 한국 개발자의 게임 프로젝트 주석(O), AI가 주로 쓴 UE5 프로젝트의 주석(K), 애니메이션 설계 문서(D)에서 1,000건당 등장 수를 쟀다. 번역체 행은 한국어 기술 글쓰기 가이드(W)를 근거로 한다. 말뭉치 수치가 아니라서 `review`와 `density`로만 둔다. 자세한 내용은 [glossary/README.md](skills/style/glossary/README.md#evidence)에 있다.

## 검사 스크립트

스킬이 교정할 때 직접 실행한다. 사람이 따로 돌려도 된다.

```
python skills/style/scripts/ko_lint.py --summary <폴더>
python skills/style/scripts/ko_lint.py --kind replace,review,density <파일>
```

C++, C#, Python, GDScript 의 주석, ini 의 `DevComment`, Markdown 의 코드 밖 본문만 읽는다. 결과는 후보일 뿐이다. `replace`는 거의 항상 고칠 것, `review`는 문맥을 보고 정할 것, `density`는 한 파일에 몰리면 문제인 표현이다. 검사 결과 예시(한국어 주석 1,000줄당 후보): 사람이 쓴 코드 64~91건, AI가 쓴 코드 1,091건.

## 프로젝트 용어

프로젝트가 따로 정한 말은 프로젝트 루트의 `.claude/ko-gamedev/terms.md`에 둔다. 용어집과 같은 표 형식으로 행을 더하고, `Allow` 표로 기본 규칙을 끈다. 예를 들어 락온을 하드락 대신 쓰는 프로젝트, 자체 그래프에서 `전이`를 용어로 정한 프로젝트가 여기에 적는다. 형식은 [glossary/README.md](skills/style/glossary/README.md#project-terms-file)를 따른다.

## 범위 밖

영어 문서, 플레이어에게 보이는 UI·현지화 문자열, 게임 개발과 무관한 일반 글, 코드 로직 변경은 다루지 않는다. 프로젝트 지침이 주석을 영어로 쓰라고 정했으면 새 주석은 영어로 쓰고, 기존 한국어 주석은 다듬을지 영어로 옮길지 먼저 묻는다.
