# game-ui — 게임 UI 화면 설계 지침

게임 화면(메뉴, HUD, 대사창, 수첩과 증거 화면, 지도, 육성·관리 허브, 이벤트 장면, 전투, 설정, 상점, 결과 화면)을 기획하거나 시안을 만들거나 리뷰할 때 따르는 지침이다. 프로젝트 UI 규칙 파일과 엔지니어용 구현 명세도 만든다. 최종 판단은 사람이 한다.

```
/plugin install game-ui@jaykop
```

| 스킬 | 명령 | 하는 일 |
|---|---|---|
| screen | `/game-ui:screen` | 화면 설계, 시안, 리뷰, UI 규칙 파일, 구현 명세 |

명령 이름을 외우지 않아도 된다. "인벤토리 화면 설계해 줘", "이 HUD 리뷰해 줘", "UI 규칙 문서 만들어 줘", "UI 기획서 엔지니어용으로 써 줘" 같은 말로도 불린다. 화면이 필요한 메커니즘을 기획할 때도 스스로 불러 쓴다.

```
/game-ui:screen 설계 상점 화면
/game-ui:screen 리뷰만 docs/ui/inventory.md
/game-ui:screen 규칙
/game-ui:screen 인계 결과 화면
```

## 모드

| 모드 | 하는 일 |
|---|---|
| `설계` (기본) | 흐름 점검 → 화면마다 요구사항 카드(목적, 결정 하나, 기능, 글자 수 상한이 붙은 요소) → 레퍼런스 화면 구조 확인 → 초점·보조·상세·하위 화면 층 나누기 → 금지 패턴과 비주얼 체크리스트 점검. 시안은 요청할 때만 만들고, 시안마다 초점과 완성도 단계(D·C·B·A)를 적는다 |
| `리뷰만` | 파일을 고치지 않고 화면별로 결정, 초점, 금지 패턴, 체크리스트 결과, 확인할 것을 보고한다. 캡처 리뷰에서는 정지 화면으로 확인하지 못한 것(동작, 사운드, 앞뒤 화면)을 따로 적는다 |
| `규칙` | 프로젝트의 `.claude/game-ui/rules.md` 를 만들거나 고친다. 톤 앤 매너 키워드와 색은 정하지 않고 OK·NO 예시가 붙은 후보를 제안한다 |
| `인계` | 엔지니어용 구현 명세(동적 요소, 상태, 연출 목록, 이름 규칙, 드로잉 계층, 해상도·세이프 영역, 현지화, 플랫폼)를 쓰거나 구현된 화면을 검수한다 |

## 핵심 원칙

전체 21개는 [SKILL.md](skills/screen/SKILL.md#principles-always)에 있다. 자주 걸리는 것만 추린다.

- 한 화면에는 초점 하나를 크게 둔다. 두 번째, 세 번째로 읽힐 것도 크기와 대비로 정한다.
- 결정하는 화면과 읽는 화면을 나눈다. 결정 화면에는 그 결정에 영향을 주는 정보만 둔다.
- 목록과 표를 UI라고 내놓지 않는다. 카테고리는 스냅으로 넘기고, 선택한 항목 하나의 정보만 보여 준다.
- 이유와 숫자는 상세 층(툴팁이나 하단 고정 도움말 영역)으로 보낸다. 호버, 포커스, 길게 누르기를 모두 지원하고, 패드·터치 중심 플랫폼에서는 하단 고정 영역을 우선한다.
- 레퍼런스 게임은 메커니즘이 아니라 실제 화면 구조(한 번에 보이는 것, 넘기는 방법, 선택하는 방법)를 출처와 함께 확인한다.
- 실제 문구를 최대 글자 수로, 가장 긴 언어 기준으로 넣고 배치한다.
- 100번째 사용을 기준으로 설계한다. 긴 연출에는 스킵을 두고, 오가는 요소는 가깝게 둔다.
- 사용자가 요청하지 않은 화면이나 단계를 넣지 않는다. 넣고 싶으면 근거와 함께 제안한다.

## 프로젝트 파일

스킬 폴더는 플러그인 업데이트 때 덮어써진다. 프로젝트 값은 프로젝트에 둔다.

| 파일 | 내용 |
|---|---|
| `.claude/game-ui/rules.md` | 플랫폼과 입력 장치, 기준·최소·최대 해상도, 화면 비율, 세이프 영역, 최소 클릭 크기, 언어, 색각이상 대응, 톤 앤 매너, 색 역할, 폰트, 텍스트 규칙, 공용 컴포넌트. 양식은 [reference/project-rules.md](skills/screen/reference/project-rules.md#template) |
| `.claude/game-ui/references.md` | 프로젝트에서 새로 확인한 레퍼런스 화면 구조와 출처 |

파일이 없어도 동작한다. 화면에 필요한 값만 묻고 나머지는 "모름"으로 두며, `규칙` 모드로 파일을 만들지 제안한다.

우선순위는 사용자의 요청, 프로젝트 지침(CLAUDE.md, AGENTS.md), 프로젝트 UI 규칙 파일, 프로젝트 전용 화면 스킬(예: VN 스킬), 이 스킬 순서다. 엔진 연결이나 작품 전용 규칙(대본 형식, 엔진 hook)은 프로젝트 스킬에 둔다.

## 출처

규칙마다 출처 표시가 붙어 있다.

- `B p.N`: 오타가키 사야코, 『플레이어를 생각하는 게임 UI 디자인 노하우』(김모세 옮김, 한빛미디어)의 N쪽. 책의 내용은 요약하고 다시 쓴 것이다. 그림과 전체 예시는 책에 있다.
- `F`: 비주얼 노벨 시제품 두 개(추리 VN, 육성 VN, 2026-11)에서 사용자가 지적한 내용. 같은 실수가 두 작품에서 되풀이되어 원칙이 되었다.

레퍼런스 화면 구조의 출처(공략 위키, 리뷰, 플레이 기록)는 [screen-references.md](skills/screen/reference/screen-references.md#sources)에 있다.

## 다른 플러그인과의 관계

- `advisors` 의 기획 고문은 시스템의 재미와 원칙을 판단한다. 이 스킬은 그 시스템을 플레이어가 다루는 화면을 설계한다.
- `ko-gamedev` 는 기획 문서의 한국어 문체를 맞춘다. 플레이어에게 보이는 UI 문구는 다루지 않으며, 그 규칙은 프로젝트 UI 규칙 파일의 텍스트 규칙에 둔다.
