# 프로젝트 전용 낱말 목록 형식

<!-- ko-review: ignore -->

프로젝트에서만 쓰는 금지어·표기는 `<프로젝트 루트>/.claude/ko-review/terms.json`에 둔다. `doc_check.py`는 이 기본 위치의 파일을 읽어 내장 목록에 더한다. 프로필의 `terms_file`이 다른 위치이면 `--terms <경로>`로 넘긴다. 스크립트의 결과 분류와 문장의 실제 적절성은 구분한다. 내장 목록의 표현도 문맥에 따라 정상일 수 있다.

```json
{
  "banned": { "낱말": "대신 쓸 말과 이유" },
  "banned_soft": { "낱말": "확인할 점" },
  "banned_patterns": { "정규식": "대신 쓸 말과 이유" },
  "soft_patterns": { "정규식": "확인할 점" },
  "lexical_pairs": { "정규식": "주체와 동작이 안 맞는 이유" },
  "variant_sets": [["표기1", "표기2"]]
}
```

| 칸 | 결과 |
|---|---|
| `banned`, `banned_patterns` | 확정 문제. exit code 1 |
| `banned_soft`, `soft_patterns`, `lexical_pairs` | 확인 필요(참고) |
| `variant_sets` | 한 파일 안에서 갈리면 확정 문제, `--tree` 로 볼 때 파일 사이에서 갈리면 참고 |

- 정규식은 Python `re` 문법이다. JSON 안이라 역슬래시는 두 번 쓴다(`"\\s"`).
- 실제 문서에서 확인한 것만 넣는다. 목록은 규칙이 아니라 이미 새어나간 표현의 기록이다.
- `banned` 계열은 프로젝트의 명시적 표기 규칙이나 문맥을 좁혀 특정할 수 있는 표현에 쓴다. 정상 용례가 예상되면 `banned_soft`·`soft_patterns`·`lexical_pairs`로 둔다. API·UI 이름이나 실제 사물의 동작까지 금지하는 넓은 패턴을 만들지 않는다.
- 대체 표현에는 무엇이 모호한지와 확인할 사실을 적는다. 정규식에 걸렸다는 이유로 뜻을 추정해 치환하지 않는다. “검사 생략”을 “전체 성공”으로 바꾸는 식의 범위 확대를 피한다.
- 목록을 늘리거나 검사에 통과한 것은 문장 품질의 근거가 아니다. `polish`의 문장 기준과 완료 판단을 적용한다. `doc_check.py`는 Markdown만 검사하므로 소스·ini의 문장 검토를 대체하지 않는다.
- 금지어를 예시로 나열하는 문서에는 `<!-- ko-review: ignore -->` 를 넣어 검사에서 뺀다.
