# 에디터·설정 파일에서 읽는 설명

설정 패널, 노드 메뉴, Blueprint 같은 스크립트 노출 API, 설정 파일의 설명 칸은 코드를 읽지 않고 에셋이나 데이터를 구성하는 사람을 독자로 삼는다. 일반 문장 기준과 완료 판단은 상위 `SKILL.md`를 따른다.

## 읽는 화면을 기준으로 고르기

- Public·Private 폴더로 구분하지 않는다. 에디터에 노출되는 타입·프로퍼티·함수·열거자와 사람이 읽는 설정 설명을 포함한다.
- 항목 이름과 완결된 설명 블록을 함께 읽는다. 한 블록 안의 역할, 적용 조건, 빈 값, 예외를 묶어 고친다. 변경된 한 줄만 자연스러워졌다고 끝내지 않는다.
- 검색은 위치를 찾는 데 쓴다. 전반 교정을 요청받으면 대상 파일 목록을 따라 검색에 걸리지 않은 설명도 읽는다.

## 툴팁에 남길 정보

첫 문장은 **무엇을 설정하는지** 또는 **이 노드가 무엇을 하는지** 설명한다. 다음 문장에는 값을 고르거나 결과를 이해하는 데 필요한 조건을 붙인다.

| 설명 대상 | 필요한 정보 |
|---|---|
| 값·참조 | 적용 대상과 효과. 결과가 달라지면 단위·기준점·빈 값·0의 의미 |
| 켜기·선택지 | 켰을 때와 껐을 때의 차이, 적용되는 모드 |
| 필터·조건 | 무엇을 검사하는지, 통과·실패의 결과, 미지정 시 생략되는 검사 |
| 함수·노드 | 실행하는 일, 입력·출력, 사용자가 처리해야 할 실패와 필요한 수명·정리 조건 |
| 타입 | 고르는 목적과 주요 사용 제약. 자세한 사용 순서는 manual |

필수 서식을 채우려고 모든 항목에 기본값·실패·수명을 나열하지 않는다. 결과에 영향을 주는 내용만 남긴다. 항목 이름으로 이미 알 수 있는 말만 되풀이한 첫 문장도 고친다.

## 빈 값과 조건

- `추가 조건. 비우면 통과한다.`는 검사 대상과 성공 범위를 생략한다. 예를 들어 전이 설정이면 “전이할 때 검사할 추가 조건. 조건을 지정하지 않으면 이 검사를 생략한다.”처럼 쓴다. 다른 전이 조건까지 없어지는 것으로 쓰지 않는다.
- `비우면 조건으로 거르지 않는다.`는 생략되는 검사와 남는 판정이 불분명하다. “조건을 지정하지 않으면 클래스와 플레이어 필터만으로 대상을 고른다.”처럼 남는 판정이 확인된 경우 그 결과를 쓴다. 근거 없이 “모든 액터를 대상으로 삼는다”로 넓히지 않는다.
- 빈 참조가 기본값 유지, 자동 검색, 기능 비활성, 설정 오류 중 무엇인지 확인한다. 같은 빈 값이라는 이유로 표현을 통일하지 않는다.
- Self·Target처럼 사용자가 조건을 구성할 때 알아야 하는 값은 누가 들어오는지 밝힌다. Context 내부 저장 구조까지 설명할 필요는 없다.

위 예시는 사실 관계가 같은 경우에만 쓴다. `review`에서는 제공된 원뜻과 근거만으로 교정할 수 있는 범위에 머문다. 확인되지 않은 동작을 더해야 한다면 `needs-decision`으로 남긴다.

## 독자와 맞지 않는 정보 덜기

- “평가에 부작용이 없어야 한다”는 조건 클래스를 구현하는 사람의 의무다. 이미 구현된 조건을 고르는 설정 칸에는 이 의무를 되풀이하지 않는다. 조건 구현 API·개발 문서에서 설명한다.
- 사용자의 호출이 자원을 만들거나 기존 값을 바꾸는 사실은 부작용에 해당해도 필요한 정보다. 함수 호출자가 정리해야 하는 자원과 구독은 남긴다.
- UHT 컨테이너 제약, 모듈 역참조 방지 이유, 수정 이력은 설정 방법을 바꾸지 않으면 툴팁에서 뺀다. 필요한 구현 설명은 허용된 범위 안의 별도 주석·문서로 옮긴다.
- 긴 클래스 툴팁에 설정 절차·내부 알고리즘·예외·개발 이력을 한꺼번에 넣지 않는다. 사용 제약은 남기고 절차는 manual에 둔다. 원인이나 기술 계약이 불명확하면 삭제로 덮지 않는다.

## 사실 대조와 보존

로직 대조가 요청된 경우에만 선언·기본값, 값을 읽는 분기, 직접 호출 대상, 필요한 종료 처리를 읽는다. 켜짐·꺼짐, 빈 값·0·음수, 정상 완료·취소·중단을 구분한다. UI의 입력 범위를 실행 중 보장으로 쓰지 않는다. `review`에서는 그 스킬의 제한이 우선한다.

실행 로직, 식별자, 기본값, 문자열, 메타데이터는 고치지 않는다. 원래 인코딩과 줄바꿈을 유지한다. 화면을 확인하지 않았으면 주석 교정을 UI 반영 확인으로 보고하지 않는다.

마지막에는 항목 이름과 최종 툴팁만 읽는다. 무엇을 지정하고 어떤 경우에 어떤 결과가 나오는지 원문이나 소스 없이 설명할 수 있어야 한다. “짧고 분명하다”는 인상이나 해시 일치로 이 읽기를 대신하지 않는다.
