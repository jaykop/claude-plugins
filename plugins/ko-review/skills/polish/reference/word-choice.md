# 낱말과 문장 판단 예시

일반 기준은 상위 `SKILL.md`를 따른다. 다음은 사실 관계가 같은 경우의 예시다. 단어를 일괄 치환하거나 원문에 없는 수치·조건·동작을 만들어 넣지 않는다.

| 원문 | 수정 방향 | 판단 이유 |
|---|---|---|
| 이 전이를 여는 트리거 | 이 전이를 요청하는 트리거 태그 | 요청과 실행을 구분한다. 실제로 요청을 받는 설정일 때 쓴다 |
| 이 태그의 창이 열려 있어야 전이가 성립한다 | 지정한 태그에 해당하는 전이 허용 구간에서만 전이할 수 있다 | 태그가 어떤 구간을 가리키는지 풀어 쓴다. “창”만 “구간”으로 바꾸고 모호한 관계를 남기지 않는다. 실제 UI 창은 바꾸지 않는다 |
| 추가 조건. 비우면 통과한다 | 전이할 때 검사할 추가 조건. 조건을 지정하지 않으면 이 검사를 생략한다 | 검사 하나와 전이 전체의 성공을 구분한다 |
| 비우면 조건으로 거르지 않는다 | 미지정 때 생략하는 검사와 남는 판정을 구체적으로 쓴다 | 남는 필터를 모르면서 “모두 통과”로 바꾸지 않는다 |
| 감쇠를 과하게 먹는다 | 감쇠가 너무 커서 회전 변화가 작아진다 | 회전 변화가 줄어드는 상황의 예다. 실제로 감쇠되는 값에 맞춰 쓴다 |
| 무기를 벗으면 | 무기의 장착을 해제하면 | 옷과 무기를 같은 동사로 뭉뚱그리지 않는다 |
| 지금 이동 입력이 노리는 걸음 단계 | 현재 이동 입력에 해당하는 걷기·달리기·질주 단계 | 입력을 의도를 가진 주체처럼 설명하지 않는다 |
| 칸이 바뀌면 이전 컬렉션을 더 붙잡지 않는다 | Data Collection 설정이 바뀌면 이전 컬렉션의 캐시 참조를 해제한다 | 설정 변경과 객체 참조 해제를 정확히 구분한다 |
| 지연이 지나면 | 지연 시간이 지나면 | 지나는 대상은 시간이다 |
| 땅 가까운 자리만 쥔다 | 선택하는 대상과 기준 높이 범위를 쓴다 | 원문에 없는 수치를 추가하지 않고 선택 조건을 설명한다 |
| 위에서 정해져 여기까지 오지 않는다 | 앞선 조건에서 결과가 정해지면 이 조건은 평가하지 않는다 | 실제로 평가를 생략하는 경우의 예다. “보류”처럼 나중에 평가한다는 이름을 붙이지 않는다 |

## 단어보다 문맥으로 판단할 것

- “열다”는 실제 창이나 파일을 여는 동작에 자연스럽다. 전이 요청·허용 구간·입력 수신을 모두 “연다”로 설명하면 구분이 사라진다.
- “부작용”은 API 호출로 바뀌는 상태를 설명할 때 필요할 수 있다. 조건을 고르는 설정 칸에 구현 원칙을 반복하는지는 별도로 판단한다.
- API 계약, 감쇠, 클램프, 폴백처럼 통용되는 전문 용어는 영어로 역번역된다는 이유만으로 틀리지 않는다. 프로젝트 용어와 독자 수준을 따르고, 풀어 쓰면 더 쉽게 이해되는 곳에서만 푼다.
- “걸러낸다”, “거른다” 자체는 정상이다. 어떤 대상을 어떤 기준으로 제외하는지 분명해야 한다.
- “장애물을 판정하는 충돌 채널”, “전환에 걸리는 시간(초)”처럼 이름과 함께 역할이 분명한 짧은 구는 유지할 수 있다.
- “풀을 쓰지 못해 소유 액터 없이 생성된 FX의 프리뷰 정리”는 수정 작업명으로는 쓸 수 있지만, 문제 해결 표의 증상으로는 부족하다. 그 열에서는 FX에 실제로 어떤 현상이 나타나는지 써야 한다. 확인한 현상이 없으면 결과를 지어내지 않고 빠진 사실을 남긴다.

화면의 이름과 설명 문장은 역할이 다르다. 상태 이름은 비활성·평가 생략처럼 실제 상태를 구분하고, 설명은 어떤 조건에서 그 상태가 되는지 쓴다. 이름을 고치는 요청이 없다면 문자열·DisplayName을 함께 바꾸지 않는다.

태그와 구간 사이의 관계를 풀어 쓴 예시는 [snflkd/fluent-korean](https://github.com/snflkd/fluent-korean/tree/ce8683f0eba8cddb91de4dcd151425ff73e60498)(MIT, 기준 커밋 `ce8683f0eba8cddb91de4dcd151425ff73e60498`)의 생략된 문장 성분과 조사·어미에 관한 기준을 참고해 보완했다. 원문의 예문을 일괄 치환 규칙으로 가져오지는 않았다.
