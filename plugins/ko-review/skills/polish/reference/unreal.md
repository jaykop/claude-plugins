# 언리얼 엔진 프로젝트의 주석

프로필 `engine` 이 `unreal` 일 때 `editor-comments.md` 와 함께 읽는다.

## 독자와 범위

- Details 패널, 에셋 설정, 노드 선택 메뉴, Blueprint, StateTree, AnimGraph 에서 읽는 설명은 에셋을 설정하는 사람이 독자다.
- `Public` 폴더 여부만으로 범위를 정하지 않는다. Editor 모듈의 `Private` 헤더도 리플렉션 타입을 정의할 수 있다.
- `UCLASS`·`USTRUCT`·`UENUM`·`UINTERFACE`·`UPROPERTY`·`UFUNCTION`의 설명 주석과 `UMETA`가 붙은 열거자 설명을 읽는다. `/** ... */`만 검색하면 한 줄 설명이나 열거자 설명을 놓칠 수 있다. 메타데이터에서 직접 지정한 설명도 위치 파악에는 포함하되 수정 권한은 구분한다.
- 리플렉션에 전달되는 주석은 코드 API 문서와 에디터 툴팁에 함께 쓰일 수 있다. 설정하는 사람에게 필요한 역할·조건·결과를 먼저 쓰고, 호출자가 지켜야 할 수명·정리·실패 조건은 보존한다. UHT·컨테이너 제약이나 모듈 의존 이유는 별도 구현 주석·문서로 옮긴다.

## 메타데이터

- `meta = (ToolTip = "...")` 가 명시돼 있으면 주석을 고쳐도 그 프로퍼티의 UI 툴팁은 바뀌지 않는다. 명시된 영어 `ToolTip` 이 한국어 주석보다 우선할 수 있으므로, 주석 교정을 UI 한글화로 보고하지 않는다.
- `DisplayName`, `Category`, `ToolTip`, `ClampMin` 같은 메타데이터 값은 고치지 않는다. `ClampMin`·`UIMin` 은 편집 화면의 입력 제한일 뿐, 실행 중 입력 검사까지 보장하지 않는다.

## Gameplay Tag 설명

- 태그 ini(`Config/DefaultGameplayTags.ini`, 프로젝트가 쓰는 `Config/Tags/*.ini` 등)의 `DevComment` 는 사람이 읽는 설명이다. 한국어로 다듬되 태그 이름, ini 키·섹션·연산자(`+`·`-`), Redirect, 등록 항목 수는 보존한다.
- 네이티브 태그 선언처럼 설명이 생성 코드로 전달되는 구조면 생성 스크립트를 읽는다. 생성 파일은 직접 고치지 않고 빌드 때 반영되는 범위를 보고한다.
- 태그를 등록만 해도 무적·피격 반응·타게팅 제외 같은 동작이 생기는 것처럼 쓰지 않는다. 그 태그를 읽는 설정과 구현(Gameplay Effect 요구 조건, 전투·타게팅 필터 등)을 확인하고 필요한 연결을 짧게 적는다.
- 입력을 구분하는 태그와 Ability System Component 가 보유하는 상태 태그를 구분해 쓴다.
- `DevComment`는 태그의 용도와 필요한 연결을 먼저 설명한다. 짧은 분류 이름만으로 충분한 태그에 사용 절차를 반복하지 않는다. 입력·상태·부위·이벤트 같은 서로 다른 역할을 모두 “실행하는 태그”로 쓰지 않는다.

## 동작 확인의 근거

- 엔진 동작을 단정해야 하면 프로젝트가 쓰는 엔진 버전의 로컬 엔진 소스를 근거로 삼는다.
- 위치 기준(액터 위치, 캡슐 표면, 충돌체 표면, 지정 소켓·지점)과 단위(초, 프레임, 도, 도/초, 언리얼 단위 cm)를 구분한다.
