# 한국어 기술 문서와 주석 다듬기

독자가 설정할 대상, 동작 조건, 결과를 한 번에 이해할 수 있도록 고친다. 맞춤법만 맞거나 금지어가 없다고 좋은 설명은 아니다.

## 경로와 우선순위

- 플러그인 폴더: `${CLAUDE_PLUGIN_ROOT}`
- 이 스킬 폴더: `${CLAUDE_SKILL_DIR}`
- 프로젝트 루트: `${CLAUDE_PROJECT_DIR}`

위 값이 경로가 아니라 변수 이름 그대로 보이면(다른 도구에서 읽는 경우 등) 이렇게 정한다. 이 스킬 폴더는 이 SKILL.md 가 있는 폴더, 플러그인 폴더는 그 두 단계 위, 프로젝트 루트는 세션을 시작한 폴더다. 아래 `<플러그인 폴더>`, `<프로젝트 루트>` 자리에는 실제 경로를 넣는다.

규칙 우선순위: 사용자의 현재 요청 → 프로젝트 지침(프로필 `instructions`, 없으면 `AGENTS.md`·`CLAUDE.md`) → 이 스킬. 프로필은 `<프로젝트 루트>/.claude/ko-review/profile.md` 이고, 양식은 `<플러그인 폴더>/shared/profile-template.md` 다. 프로필이 없어도 이 스킬은 쓸 수 있다. 그때는 사용자가 지목한 범위만 다루고, 끝에 "프로필을 만들면 문서 폴더와 제외 범위를 기억한다"고 한 줄 알린다.

## 대상과 수정 범위

- 사용자가 지목한 문서·파일을 먼저 읽는다. 범위를 넓게 요청하면 프로필 `doc_roots`·`code_roots` 안의 실제 파일을 대상으로 삼고 `exclude` 는 빼며, 벤더·생성 파일은 프로필이 없어도 뺀다. 템플릿(`doc_templates`)은 작성 기준으로만 읽는다.
- 문서 정리는 그 폴더의 템플릿을 따른다. 형식을 맞추려고 문서 전체를 다시 쓰거나 과거 기록을 현재 사양으로 바꾸지 않는다.
- 코드 주석을 요청하면 설명 주석과 API 주석만 다듬는다. 식별자, 문자열 리터럴, 리플렉션·어노테이션 메타데이터, 실행 로직은 보존한다. 프로필 `code_text_language` 의 언어로 쓰인 코드 표기를 주석 언어로 바꾸지 않는다.
- 시작 전에 `git status --short` 로 미커밋 변경을 확인하고 보존한다. 검색 결과만 읽지 말고 문단과 인접 항목을 함께 읽는다. 검색은 후보를 찾는 보조 수단이다.

## 문장을 고치는 기준

먼저 문단이 설명하는 대상과 동작을 파악하고, 어색한 문장은 의미 단위로 다시 쓴다. 특정 낱말을 다른 낱말로 일괄 치환하는 데 그치지 않는다.

1. **대상과 주체**: 무엇이 무엇을 하는지 분명한가. `자리`, `칸`, `그쪽`이 설정·노드·인스턴스 중 무엇을 뜻하는지 모호하면 정확한 대상을 쓴다. 실제 입력란이나 표의 칸을 뜻할 때는 그대로 둔다.
2. **조건과 결과**: 언제 적용되는지, 빈 값이나 실패 때 어떻게 되는지 구분되는가. 서로 다른 상태를 한 문장에 몰아넣었다면 나눈다. 원문에 없는 동작은 추정해 더하지 않는다.
3. **자연스러운 표현**: 주어와 서술어, 조사, 수식 범위가 맞는가. `서브스텝 한 칸`, `살아 있는 인스턴스`, `갈아타는 자리`처럼 실제 대상을 비유로 대신하면 `한 서브스텝`, `실행 중인 인스턴스`, `전이를 연결하는 경유 노드`처럼 설명한다.
4. **구어체의 명료성**: 친근한 말투라도 뜻이 정확하고 읽기 쉬우면 유지한다. 기존 구어체라는 이유만으로 모호한 표현을 보존하지 않는다. 모든 문장을 딱딱한 격식체로 바꾸지도 않는다.
5. **용어와 문체**: UI·API 이름은 원문을 유지하고 일반 설명은 자연스러운 한국어로 쓴다. 한 낱말을 무조건 금지하거나 유지하지 않고, 문맥에 따라 풀어 쓰면 더 분명한지 판단한다. 문서의 기본 종결 방식에 맞춘다.
6. **정보 구조**: 비교는 표, 순서는 번호 목록, 독립적인 설정은 불릿으로 쓸 수 있다. 목록·강조·줄표·경고 기호를 AI 문체라는 이유로 일괄 삭제하지 않는다. 반복 설명은 줄이되 제한과 실패 조건은 남긴다.
7. **문장 하나에 내용 하나**: 절차 문장에는 지시 하나, 설명 문장에는 사실 하나를 둔다. `~고`, `~며`, `~으나`로 절이 세 번 넘게 이어지거나 한 문장이 20어절을 넘으면 나눌 수 있는지 본다. 길이는 검토를 시작하는 신호이며 기계적인 상한이 아니다.
8. **한 용어에 한 뜻**: 문서 하나 안에서 같은 대상은 같은 낱말로 부른다. `설정`·`옵션`·`프로퍼티`나 `확인`·`검증`·`점검`을 번갈아 쓰면 독자는 서로 다른 대상으로 읽는다. 반대로 뜻이 다른 두 대상(예: 소스 대조와 사용자 빌드 확인)에 같은 낱말을 쓰지 않는다.
9. **주체를 드러낸 능동문**: `~에 의해 ~된다`, `~되어진다`처럼 행위자를 감춘 문장은 실행기·엔진·사용자 중 누가 하는지 밝혀 능동문으로 쓴다. 대상의 상태가 바뀌는 것을 말하는 문장(`태스크가 종료된다`)은 그대로 둔다.
10. **조건은 앞에, 절차는 지시형으로**: 조건은 문장 앞에 둔다(`빌드가 실패하면 로그를 연다`). 독자가 따라 하는 절차는 문서의 종결 방식에 맞춘 지시형으로 쓰고, 한 단계에 동작 하나를 둔다. 경고도 금지 사항이나 조건을 먼저 쓰고 그 이유가 되는 위험을 뒤에 쓴다.
11. **필수와 가능을 구분**: 필수는 `~해야 한다`, 가능은 `~할 수 있다`로 쓴다. `~하는 것이 좋다`, `~하면 된다`, `~할 수도 있다`처럼 필수인지 선택인지 흐린 표현은 둘 중 하나로 바꾼다. 원문의 의도를 알 수 없으면 추정하지 말고 보고한다.
12. **중요도 대신 사실**: `매우 중요하다`, `반드시 유의한다`, `간단히`처럼 정보가 없는 강조어는 지운다. 대신 지키지 않으면 무엇이 어떻게 되는지를 쓴다. `A의 B의 C의 D`처럼 명사가 이어지는 구는 조사나 서술어로 풀어 쓴다.

7~12번은 ASD-STE100(Simplified Technical English)의 원칙 가운데 한국어에 옮길 수 있는 것만 가져왔다. 영어 낱말 사전과 서식 금지 규칙은 따르지 않으며, 서식은 6번 기준을 따른다.

예시는 고정 치환 규칙이 아니라 판단 기준이다.

| 원문 | 수정 예 | 이유 |
|---|---|---|
| Conduit은 길 가운데 두는 갈아타는 자리다 | Conduit은 여러 출발지와 목적지 사이의 전이를 연결하는 경유 노드다 | 노드의 역할을 직접 설명한다 |
| 칸이 바뀌면 이전 컬렉션을 더 붙잡지 않는다 | Data Collection 설정이 바뀌면 이전 컬렉션의 캐시 참조를 해제한다 | 설정과 참조 수명을 구분한다 |
| 일반 지속 태스크는 Start → Tick들 → End다 | 일반 지속 태스크는 Start 후 매 프레임 Tick을 받고 End로 종료된다 | 호출 순서를 자연스럽게 설명한다 |
| 설정값에 의해 태그가 부여되어진다 | 실행기가 시작할 때 설정에 지정한 태그를 소유자에게 붙인다 | 행위자와 시점을 밝힌다 |
| 캐시를 비우는 것이 좋다 | 에셋을 바꾼 뒤에는 캐시를 비워야 한다. 비우지 않으면 이전 값이 남는다 | 필수 여부와 지키지 않았을 때의 결과를 쓴다 |

## 에디터·설정 파일에서 읽는 설명

에디터의 설정 패널, 노드 메뉴, 스크립트 노출 API, 설정 파일의 설명 칸처럼 **코드를 읽지 않는 사람이 보는 설명**은 `reference/editor-comments.md` 의 기준을 따른다. 프로필 `engine` 값에 맞는 엔진별 파일(예: `reference/unreal.md`)이 있으면 함께 읽는다. 없으면 일반 기준만 쓴다.

## 현재 로직과 대조하기

로직 일치 검토를 요청받았거나, 설명 변경 목록의 항목을 교정할 때는 수정 후보의 선언과 관련 구현을 함께 읽는다. 생성자·초기값, 값을 읽는 분기, 조기 반환, 종료·정리 경로와 필요한 직접 호출부까지만 확인한다. 외부 엔진·라이브러리 동작을 단정해야 한다면 그 소스나 공식 문서를 근거로 삼는다. 무관한 시스템까지 별도 리뷰로 넓히지 않는다.

- 이름·메타데이터·설명서만 보고 실행 동작을 추정하지 않는다. 설명서는 사용 방법의 맥락이고, 현재 실행 동작은 구현에서 확인한다.
- 조건 평가의 조기 종료, 정상 완료와 중단의 차이, 설정이 없을 때의 대체 동작을 빠뜨리지 않는다.
- 주석과 구현이 다르면 근거가 있는 설명을 고친다. 주석에 맞추려고 로직을 바꾸지 않는다. 코드 결함이나 정하지 않은 동작으로 보이면 별도 쟁점으로 보고한다.
- 요청에 포함된 관련 소스 읽기는 교정의 일부다. 빌드·테스트·lint·별도 코드 검사를 실행할 권한은 아니다. 프로필 `check_runs` 가 `agent` 가 아니면 사용자가 요청할 때만 실행한다.

## 설명서와 설정 파일

- 설명서는 현재 사용 절차·UI 이름·설정 표·제한을 관련 구현과 대조한다. 이미 제공하는 기능을 예정으로 설명한 문장은 현재 사용법으로 고친다. 별개의 과거 확인 날짜·보고 범위는 유지한다.
- 프로필 `data_comment_files` 의 설명 칸은 사람이 읽는 설명이므로 한국어로 다듬되 키 이름, 섹션, 연산자, 등록 항목 수는 보존한다. 설명이 생성 코드로 전달되는 구조면 생성 스크립트를 읽고, 생성 파일은 직접 고치지 않는다.
- 설정 항목을 등록만 해도 어떤 동작이 생기는 것처럼 쓰지 않는다. 그 항목을 읽는 설정과 구현을 확인하고 필요한 연결을 짧게 설명한다.
- 설명 변경 목록이 주어지면 지정한 항목과 그 주변 문단·관련 구현부터 읽는다. 목록만으로 논리 일치를 확정하지 않고, 작업과 무관한 파일로 범위를 넓히지 않는다. 목록은 검토하지 않은 문장의 품질까지 보증하지 않는다.

## 의미와 근거 보존

표현만 고친 문장은 원문과 대조해 적용 조건, 부정, 횟수, 단위, 기본값, 수명, 실패 조건이 유지됐는지 확인한다. 로직 불일치를 바로잡은 문장은 확인한 구현을 기준으로 대조한다. 이 대조는 문장 수정의 일부이며 빌드·테스트·별도 코드 검사를 뜻하지 않는다.

- API 주석은 역할뿐 아니라 호출자가 알아야 할 입력·반환값, 수명, 부작용, 실패 조건을 보존한다.
- 구현 주석은 동작을 되풀이하기보다 구현 이유, 엔진·플랫폼 제약, 경계 조건을 설명한다.
- 과거 확인 날짜와 결과를 보존한다. 표현만 고쳤다면 실행 확인을 새로 했다고 기록하지 않는다. 문서 갱신일은 실제 수정일로 바꾼다.
- 뜻이 불명확한 참조나 기술 내용의 불일치는 근거가 있는 범위까지만 정리하고 남은 의문을 보고한다. 문장을 고치면서 정하지 않은 설계를 확정하지 않는다.
- 한 표현의 잘못된 사용을 발견했다고 금지어 목록에 자동으로 넣지 않는다. 문맥에 따라 정상인 표현은 문맥으로 판단한다. 목록에 넣을 만하면 사용자에게 제안한다(형식: `<플러그인 폴더>/shared/terms-format.md`).

## 보조 스크립트와 다른 스킬

`doc_check.py` 는 링크·앵커·금지어·표기 갈림 후보를 찾는 읽기 전용 도구다. Markdown 문서를 고쳤거나 검토 범위에 문서가 있으면 실행한다.

```
python "<플러그인 폴더>/scripts/doc_check.py" <문서들>
```

`python` 이 없으면 `python3` 으로 실행한다. 프로젝트 전용 목록(`terms_file`)이 있으면 자동으로 함께 읽는다. 걸린 낱말도 문맥을 읽고 판단한다. 스크립트 통과를 문장 품질의 근거로 쓰지 않는다.

맞춤법·문체 전용 스킬(예: `korean-skills` 의 `grammar-checker`, `humanizer`, `style-guide`)이 설치돼 있으면 특정 문제를 푸는 데 필요한 참고만 읽는다. 모든 스킬과 검사를 순서대로 돌리는 의무 절차를 만들지 않는다. 기술 문서에 맞지 않는 산문 규칙은 적용하지 않는다.

## 수정과 보고

- 사용자가 검수와 수정을 요청했으면 뜻이 분명한 문장은 직접 고친다. 고칠 때마다 다시 허락을 받지 않는다. 검토나 제안만 요청했으면 그 범위로 제시한다.
- 이 프로젝트가 설명 변경 목록을 쓰고(프로필이 있고 `queue_dir` 아래에 목록이 있다) 지금 작업에 목록이 있으면, 작성하는 쪽은 `record` 스킬로 고친 설명을 등록한다. 검토하는 쪽이 대기 항목을 고친 경우는 `review` 스킬의 `finish` 로 최종 내용을 기록하고, 자기 수정을 다시 등록하지 않는다.
- 완료 보고에는 수정 범위, 대표적인 전후 예시, 남은 모호한 내용, 실제로 실행한 검사를 간결하게 적는다. 읽지 않은 파일이나 실행하지 않은 검사를 포함해 전체 통과라고 보고하지 않는다. 점수표, 스크립트 원문 출력, 사소한 수정의 전수 목록은 요청이 있을 때만 낸다.
