# 설명 변경 부분 검토 (검토 쪽)

목록에 남은 대기 항목만 읽고 교정한다. 교정 기준은 같은 플러그인의 `polish` 스킬이고, 목록 형식과 명령은 `<플러그인 폴더>/shared/queue-format.md` 다. 필요한 단락만 읽는다.

## 경로

- 플러그인 폴더: `${CLAUDE_PLUGIN_ROOT}`
- 프로젝트 루트: `${CLAUDE_PROJECT_DIR}`

값이 변수 이름 그대로 보이면 플러그인 폴더는 이 SKILL.md 의 두 단계 위 폴더, 프로젝트 루트는 세션을 시작한 폴더다. 명령은 프로젝트 루트에서 실행한다. 아래 `<도구>` 는 `python "<플러그인 폴더>/scripts/review_queue.py"` 다(`python` 이 없으면 `python3`).

## 대상 고르기

- 프로젝트 지침과 사용자가 정한 범위를 따른다. `git status --short` 와 그 작업의 메모를 읽는다.
- 목록 폴더는 프로필(`<프로젝트 루트>/.claude/ko-review/profile.md`)의 `queue_dir`, 없으면 `.claude/ko-review/queue` 다.
- 작업을 지정받았으면 `<queue_dir>/<task>.descriptions.json` 을 쓴다. 대기 목록 전체를 요청받았으면 그 폴더의 `*.descriptions.json` 만 찾아 작업별 `taskId` 와 대기 항목 수를 요약하고 대기 항목부터 처리한다. 완료된 목록의 소스까지 읽지 않는다.
- `<도구> pending <task>` 로 현재 내용과 기록을 맞춘다. 설명·근거가 바뀌었거나 위치가 사라진 항목은 이 명령이 대기로 돌린다. `unassignedChanges` 는 파일 단위의 등록 누락 알림이다. 파일 안의 모든 변경 구간이 등록됐다는 보장이 아니다.
- 항목·위치가 없으면 지정받은 커밋·파일 범위로만 진행한다. 목록이 없다는 이유로 전체 프로젝트 검토나 기록 복원을 시작하지 않는다. 시작 전 변경이나 작성자의 기록이 모호하면 확인할 수 있는 항목만 진행하고 남은 범위를 알린다.

## 읽기와 교정

1. 항목의 `selector` 와 `evidence` 로 실제 설명, 인접 문단, 관련 구현을 읽는다. 설명의 결론을 믿지 말고 필요한 기본값·분기·실패·종료 조건을 직접 대조한다. anchor 가 사라졌거나 여러 줄과 맞으면 위치를 바로잡기 전에는 완료로 기록하지 않는다.
2. 고치기 전에 `<도구> begin <task> --id <id> --reviewer <이름>` 으로 token 과 스냅샷을 받는다. 이름은 프로필 `reviewer` 값(없으면 자기 이름)이다.
3. `polish` 스킬의 기준으로 자연스러운 한국어와 로직 일치를 검토하고, 뜻이 분명한 설명은 직접 고친다. 식별자, 일반 문자열, 메타데이터, 실행 로직, 설정 파일의 키는 보존한다. 생성 파일은 고치지 않는다. 문서를 고쳤으면 `doc_check.py` 로 링크·앵커를 확인한다.
4. 구현 결함이나 정하지 않은 동작이면 근거와 필요한 결정을 남기고 `needs-decision` 으로 기록한다. 설명에 맞추려고 코드를 바꾸지 않는다.

## 결과 기록

- `<도구> finish <task> --id <id> --token <token> --note "결과"` 로 기록한다. 판단이 필요하면 `--status needs-decision` 을 붙인다.
- 설명을 직접 고쳤으면 최종 본문을 다시 읽은 뒤 `<도구> snapshot <task> --id <id>` 가 출력한 `description.sha256` 을 `--description-hash` 로 넘긴다. 해시 계산은 품질 검토를 대신하지 않는다.
- 검토 중에 근거가 바뀌었거나 최종 설명 해시가 다르면 도구가 완료 기록을 거절한다. 현재 내용을 다시 읽고 `begin` 부터 다시 한다. 다른 작업자의 변경을 되돌리지 않는다.
- 자기가 고친 내용은 최종 내용으로 `finish` 한다. 작성 쪽 방식(`register`)으로 다시 등록해 자기 수정이 계속 대기에 남게 만들지 않는다. 이후 작성 쪽이 설명·근거를 또 고치면 다음 `pending` 에서 다시 대기가 된다.
- 목록 파일을 직접 고쳐야 한다면 기존 내용과 스냅샷을 보존하고, 기록 직전에 현재 내용을 다시 읽는다. 도구 오류를 성공으로 바꿔 적지 않는다.

## 지키는 것

- 빌드·테스트·lint·별도 코드 검사·테스트 코드 추가는 하지 않는다. 프로필 `check_runs` 가 `agent` 이고 사용자 요청 범위에 있을 때만 예외다.
- 커밋·이슈 댓글 같은 외부 게시는 프로젝트 지침의 승인 절차를 따른다.
- 완료 보고에는 처리한 작업과 항목, 대표 교정 예, 판단이 필요한 항목, 실제로 실행한 검사를 적는다. 요청 범위의 문서와 작업 메모를 갱신한다.
