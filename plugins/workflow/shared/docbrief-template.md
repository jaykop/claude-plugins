# 문서 지시서 양식

프로필 `doc_writer: codex` 일 때 쓴다. 구현한 쪽(Claude)이 `feature-doc-sync` 에서 이 양식으로 사실을 적고, 문서를 쓰는 쪽(Codex)이 `doc-draft` 로 manual·devlog·plan 을 쓴다. 위치는 `<threads_dir>/<작업 ID>.docbrief.md` 다. 작업 ID 는 인계 메모 파일 이름과 같게 쓴다.

지시서에는 **사실만** 적는다. 문서에 들어갈 문장을 미리 써 두지 않는다. 미리 쓴 문장이 있으면 쓰는 쪽이 그 표현을 따라가서 문장 품질이 올라가지 않는다. 대신 사실 하나하나에 근거를 붙이고, 빠진 사실이 없게 쓴다. 문서에 들어갈 사실이 지시서에 없으면 쓰는 쪽은 그 내용을 쓰지 않는다.

```markdown
# 문서 지시서 — <작업 ID>

작업: <작업 ID> / 이슈: <#번호 또는 없음> / 작성: <구현한 쪽> <YYYY-MM-DD>
상태: 작성 대기 <!-- 작성 대기 → 작성됨 → 대조 완료 | 재작성 대기 → 재작성됨 → 대조 완료 -->

## 쓸 문서

| 경로 | 종류 | 할 일 | 읽을 템플릿 |
|---|---|---|---|
| <docs/manual/Topic.md> | manual / devlog / plan / index | 새로 씀 / "<절 제목>" 절 갱신 / 목록 한 줄 추가 | <템플릿 경로 또는 -> |

## 사실

문서에 들어갈 동작·설정·조건·단위·결과·제한. 사실을 하나씩 한 줄에 적는다. 코드 이름과 실제 동작으로 적고, 비유나 지어낸 말을 쓰지 않는다. 근거는 코드 경로:줄, 커밋, 이슈, 사용자 확인 기록 가운데 하나 이상.

| ID | 사실 | 근거 | 들어갈 문서 |
|---|---|---|---|
| F-1 | | | |

## 결정

devlog·plan 에 들어갈 선택과 그 이유. 확정한 사람과 시점이 없으면 "미확정"에 둔다.

| ID | 결정 | 이유 | 확정(누가·언제·어디서) | 고려했으나 고르지 않은 안 |
|---|---|---|---|---|
| D-1 | | | | |

## 확인 상태

| 대상 | 확인 방법·수행자 | 결과 | 확인하지 않은 범위 |
|---|---|---|---|

## 미확정 사항

문서에 "정하지 않음"으로 남길 것. 쓰는 쪽은 이 항목을 현재 사양처럼 쓰지 않는다.

## 쓰지 않을 것

- 지시서에 없는 동작, 한계, 수치, 원인 추정
- 확인하지 않은 빌드·실행 결과
- <작업별로 더할 것: 공개 문서에 넣지 않을 로컬 경로, 내부 기록 ID 등>

## 작성 결과

쓰는 쪽이 채운다. 문서마다 작성한 절과 각 절에 쓴 사실·결정 ID 를 적는다. 지시서만으로 작성할 수 없어 비워 둔 곳은 그 이유도 적는다.

## 대조 결과

구현한 쪽이 채운다. 문장은 고치지 않고 위치와 문제만 적는다.

| 문서 위치 | 문제 | 맞는 사실(ID 또는 근거) | 처리 |
|---|---|---|---|
| <경로 + 절 제목 또는 고유 문구> | 사실과 다름 / 지시서에 없는 내용 / 빠진 사실 / 미확정을 확정처럼 씀 | | 재작성 / 사용자 확인 |
```
